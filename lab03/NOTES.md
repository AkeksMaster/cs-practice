\# Журнал воркшопа Git



\## 1. Сравнение версий и поиск изменений



\### git log --oneline --stat



Команда показывает историю коммитов и статистику изменений файлов. Я увидел, какие файлы изменялись и сколько строк было добавлено или удалено.



\### git diff HEAD\~2 HEAD -- lab03/calc.py



Команда сравнивает файл между двумя коммитами. Я сравнил первую и третью версии калькулятора и увидел добавление вычитания и умножения.



\### git show HEAD\~1



Команда показывает информацию о конкретном коммите и изменения, которые он содержит. Я изучил коммит, в котором было добавлено вычитание.



\### git log -S"def" --oneline -- lab03/calc.py



Команда ищет коммиты, в которых изменилось количество вхождений указанной строки. В моём файле пока нет def, поэтому поиск может не показать результатов.



\### git blame lab03/calc.py



Команда показывает, к каким коммитам относятся отдельные строки файла. Это помогает понять историю изменения кода.



\### Различие команд



git diff сравнивает состояния файлов и показывает различия между ними.



git show показывает содержимое и изменения конкретного коммита.



git log показывает историю коммитов, а параметр --stat добавляет статистику изменений.



\## 2. Восстановление файла



\### git status



Команда показала, что файл calc.py изменён и эти изменения ещё не были сохранены в коммите.



\### git restore lab03/calc.py



Команда восстановила файл из индекса. Поскольку файл не был добавлен в индекс, он вернулся к состоянию последнего коммита. Незакоммиченные изменения рабочего файла были отменены.



\### git restore --source=HEAD\~2 lab03/calc.py



Команда восстановила более старую версию файла из указанного коммита. В моём случае калькулятор вернулся к первой версии, в которой была только операция сложения.



\### git diff



Команда показала различия между восстановленной старой версией файла и последним коммитом.



\### Вывод



git restore отменяет изменения рабочего файла. Параметр --source позволяет выбрать коммит, из которого нужно восстановить файл. Перед восстановлением важно убедиться, что нужные изменения не будут потеряны.



\## 3. Отмена ошибочного коммита



\### git revert HEAD



Команда создала новый коммит, отменяющий изменения предыдущего коммита. Я добавил операцию деления без проверки деления на ноль, а затем отменил её с помощью git revert.



\### Отличие от git reset --hard



git revert сохраняет исходный коммит в истории и создаёт новый коммит, отменяющий его изменения.



git reset --hard перемещает текущую ветку к выбранному коммиту и сбрасывает индекс и рабочие файлы. Незакоммиченные изменения при этом могут быть потеряны.



Для опубликованной истории обычно безопаснее использовать git revert, потому что он не переписывает историю существующих коммитов.



\## 4. Тег рабочей версии



\### git tag -a v1.0 -m "Рабочая версия калькулятора"



Команда создала аннотированный тег v1.0 и привязала его к текущему коммиту. Тег отмечает рабочую версию калькулятора.



\### Различие тега и ветки



Ветка — изменяемый указатель на коммит, который перемещается при добавлении новых коммитов в эту ветку.



Тег — имя для определённого коммита. Он используется для обозначения версии программы и не перемещается автоматически при создании новых коммитов.
